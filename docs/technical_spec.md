# Astra Gov AI – Technical Specifications

## Overview

This document defines the technical contracts for the **Astra Gov AI platform**.  
It specifies the API endpoints, JSON request and response formats, AI agent prompts, data schemas, real-time update logic, and deployment setup.

The purpose of this file is to ensure consistent communication between:

- Frontend (Next.js)
- Backend (FastAPI)
- AI Agents (LangGraph / Gemini)
- Databases (Supabase + ChromaDB)

---

# 1. API Endpoints (FastAPI)

All backend endpoints follow a versioned structure.

Base path:


/api/v1


---

## A. Global Orchestrator

### Endpoint


POST /api/v1/process


### Description

This is the **primary entry point for all user chat requests**.  
The endpoint receives the user's natural language query and forwards it to the **Orchestrator Agent**.

The orchestrator determines which specialized agent should process the request.

Possible routing targets:

- Scheme Agent
- Business Agent
- Complaint Agent

---

### Request Body

```json
{
  "user_id": "uuid-string",
  "query": "I want to start a cafe and need to know about food safety grants.",
  "context": {
    "location": "Salem",
    "age": 28
  }
}
Response Logic

The Orchestrator analyzes the query.

Intent classification is performed.

Entities are extracted.

The appropriate specialized agent is executed.

A unified JSON response is returned to the frontend.

B. Scheme / Business RAG Service
Endpoint
POST /api/v1/retrieve
Description

Internal service used by agents to retrieve relevant context from the ChromaDB vector database.

The endpoint performs semantic similarity search against document embeddings.

This allows the AI to retrieve relevant sections from:

Government scheme PDFs

Business licensing documents

Regulatory guidelines

Response Example
{
  "results": [
    {
      "source": "Food_Safety_Guidelines.pdf",
      "page": 8,
      "snippet": "Restaurants must obtain an FSSAI license before operation."
    },
    {
      "source": "Startup_India_Schemes.pdf",
      "page": 12,
      "snippet": "Food service businesses may qualify for startup incubation grants."
    }
  ]
}
C. Activity Tracker
Endpoint
PATCH /api/v1/activity/update
Description

Updates the checklist stored in the Supabase user_activities table when a user completes a task.

The checklist is stored as a JSONB field.

This allows users to track progress for activities such as:

Business setup steps

Government scheme applications

Request Payload
{
  "activity_id": "uuid",
  "task_index": 2,
  "completed": true
}
Expected Behavior

Backend retrieves the activity record

Updates the checklist JSON

Recalculates progress percentage

Stores updated state in Supabase

Example progress update:

Progress: 40% → 60%
2. Agent System Prompts

The AI agents use structured system prompts to guide reasoning and maintain consistent behavior.

Orchestrator Agent Prompt
You are the Astra Gov Dispatcher.

Your task is to categorize the user query into one of the following intents:

SCHEME
BUSINESS
COMPLAINT

Extract useful entities such as:
location
age
business type
department references

If the query is ambiguous, ask a clarifying question.

Output ONLY a JSON object with the following keys:

intent
entities
next_step
Example Output
{
  "intent": "BUSINESS",
  "entities": {
    "business_type": "cafe"
  },
  "next_step": "retrieve_business_guidelines"
}
RAG Agent Prompt (Grounded Responses)
Use the provided context from official government documents to answer the user's query.

If the answer is not present in the provided context, clearly state that no official information was found.

Always include:
- Source document name
- Page number

If the request involves procedures or steps, format the response as a clear step-by-step guide.

4. Real-Time Subscription Logic (Supabase)

To enable transparent status updates, the frontend subscribes to realtime database changes.

The subscription listens for updates on the complaints table.

React / Next.js Client Listener
const channel = supabase
  .channel('public:complaints')
  .on(
    'postgres_changes',
    {
      event: 'UPDATE',
      schema: 'public',
      table: 'complaints'
    },
    payload => {
      console.log('Status updated by Government:', payload.new.status);
      toast.success(`Your complaint status is now: ${payload.new.status}`);
    }
  )
  .subscribe();
Behavior

Whenever a government official updates the complaint status:

Pending → In Progress → Resolved

The frontend interface updates automatically.

This ensures real-time transparency for citizens.
